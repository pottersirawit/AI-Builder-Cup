บังคับตามกติกา

  • ต้องใช้ Gemini หรือ Gemma
  • ต้อง deploy บน Cloud Run หรือ Firebase
  • ส่ง proposal PDF + ต้นแบบใช้งานได้ + วิดีโอ ≤ 3 นาที

น้ำหนักคะแนน

  • 40% Technical merit และการใช้ Gen AI
  • 25% ตรงโจทย์และ impact
  • 25% ความใหม่
  • 10% UX

สิ่งที่ "แนะนำ" แต่ไม่บังคับ

BigQuery, Earth Engine, Pub/Sub, Vision AI เป็นรายการแนะนำในโจทย์ ไม่มีในกติกาบังคับ ใช้เท่าที่มีเหตุผลจริง

2. แหล่งข้อมูล ตรวจแล้ว 29 ก.ย. 2026

แหล่งให้อะไรสถานะถ้าใช้ไม่ได้
Google Weather API (Maps Platform)ปัจจุบัน + รายชั่วโมง 240 ชม. + เตือนภัย ครอบคลุมไทย ฟรี 10,000 ครั้ง/เดือนพร้อมใช้ไม่ต้องมีสำรอง ใช้เป็นแกนของฝน
Google Routes APIเวลาเดินทางคิดรถติด ฟรี 5,000 ครั้ง/เดือนแบบ traffic awareพร้อมใช้เก็บ cache ต่อเส้นทาง 15 นาที กันโควตาหมดตอนเดโม
กรมอุตุฯ NWP API (data.tmd.go.th/nwpapi)รายชั่วโมง 72 ชม. ความละเอียด 3 กม. JSON, OAuth tokenต้องลงทะเบียนใช้เป็นแหล่งที่สองให้ Gemini เทียบสองพยากรณ์ ถ้าไม่ทันก็ตัดได้ ไม่กระทบแกน
สำนักการระบายน้ำ กทม.ระดับคลอง จุดน้ำท่วม เรดาร์ฝน แต่ไม่มี API สาธารณะ เว็บเป็น SPA ที่เรียกตรงไม่ได้จุดเสี่ยงดึงผ่าน ThaiWater ของ HII (thaiwater.net/bma) ที่สะท้อนข้อมูลเดียวกัน หรือ relay ของโปรเจกต์ flood2026 (199 สถานี ทุก 5 นาที) ถ้าล้มทั้งคู่ ใช้รายงานผู้ใช้เป็นเซ็นเซอร์แทน
Google Flood Hub / Flood Forecasting APIไทยอยู่ในพื้นที่ครอบคลุมแม่น้ำ แต่ API จำกัดเฉพาะ pilot ต้องรอคิว "หลายเดือน"ไม่ทันไม่พึ่ง ใส่ใน proposal เป็นแผนต่อยอด
เรดาร์ / nowcastกรมอุตุฯ มีแค่รูป JPG · RainViewer มี JSON ฟรี (ใช้ส่วนตัว ต้องให้เครดิต)ใช้ได้จำกัดใช้ RainViewer โชว์เฟรมย้อนหลังในเดโม ไม่เอาเป็นข้อมูลตัดสิน
Google Calendar APIนัดพร้อมสถานที่และเวลาพร้อมใช้OAuth verification สำหรับแอปสาธารณะใช้เวลา ใช้โหมด testing กับบัญชีทีมในรอบนี้
Gmail APIอีเมลยืนยันตั๋วprivacyscope gmail.readonly เป็น restricted scope ต้องผ่านการตรวจ ในรอบนี้ใช้บัญชีทดสอบ และแสดงจอขออนุญาตชัดเจนในเดโม

3. AI ทำอะไรจริง เพื่อคะแนน 40%

Agent ตัดสินใจ ไม่ใช่สรุปข้อความ

Gemini ได้รับ tools (weather, route, floodpoints, calendar) แล้วเลือกเรียกเองตามบริบท เช่น มีนัด 18:30 → ดูฝนช่วง 16:00 ถึง 18:30 บนเส้นทาง → ลองเวลาออก 3 ค่า → เลือกค่าที่ทัน คืนคำตอบเป็น JSON ที่ตรวจสอบได้ ก่อนแปลงเป็นภาษาคน

Vision เป็นเซ็นเซอร์ชุมชน

รูปจากผู้ใช้ + GPS → Gemini ประเมินระดับน้ำ (ซม.) พร้อมความมั่นใจ → ยืนยันกับรายงานใกล้เคียง → เข้าเป็น floodpoint ให้ agent ตัวอื่นใช้ต่อ นี่คือคำตอบเวลาข้อมูลทางการเข้าไม่ถึง

ภาษาคนที่มีตัวเลขเสมอ

prompt บังคับให้ทุกคำตอบมีเวลาออก เวลาถึง และเหตุผลอ้างข้อมูล กันปัญหา "พยากรณ์ลอย ๆ" แบบเว็บทั่วไป ประเมินได้ด้วย eval ง่าย ๆ: มีเวลาไหม อ้างข้อมูลจริงไหม

รู้จักผู้ใช้

เก็บการตัดสินใจย้อนหลังใน Firestore เพื่อให้ agent รู้ว่าคนนี้ปกติกลับ 18:00 ทางรัชดา ใช้รถ ไม่ต้องตั้งค่า (ต่อยอด ไม่อยู่ในรอบแรก)

5. คำถามที่ทีมควรตอบก่อน commit

  • ใครเคยใช้ Vertex AI tool calling จริง ถ้ายังไม่มี ให้คนนั้นทำ spike 1 วันแรกก่อนแบ่งงานอย่างอื่น
  • เดโมวิดีโอจะใช้ข้อมูลสดของวันอัด หรือใช้ replay ของวันฝนตกจริง (แนะนำ replay เพราะควบคุมดราม่าได้)
  • รับความเสี่ยงเรื่อง ThaiWater ล่มระหว่างเดโมไหม ถ้าไม่ ให้ snapshot ข้อมูลไว้ใน Firestore เป็นสำรองตั้งแต่ต้น
  • Gmail จะเอาเข้ารอบแรกจริงไหม เมื่อกรรมการจะถามเรื่อง privacy แน่ ถ้าตอบไม่ทันให้ตัดออกจากวิดีโอแต่คงไว้ใน proposal
  • ชื่ออังกฤษสำหรับกรรมการ JAPAC ตัดสินใจก่อนเขียน proposal
