แผนถ่ายทำฉบับเต็ม (ฉบับที่สองหลังผ่านการตรวจของ agent สามบทบาท: ผู้ตรวจข้อเท็จจริง กรรมการ และผู้ผลิตวิดีโอ): เรื่องที่ต้องตัดสินใจเช้านี้, กติกาที่ตรวจแล้ว, storyboard ทีละวินาที พร้อมบทพูดภาษาอังกฤษ, ขั้นตอนอัดหน้าจอ, ความเสี่ยงที่วัดจากการรันจริง, ตารางงาน 3 วัน และขั้นตอนอัปโหลด

สรุป

  • ภาษาอังกฤษบังคับ ("All code, documentation, and presentations must be in English") บทพูดจึงเป็นอังกฤษ และเนื่องจากเราเพิ่งทำโหมดภาษาอังกฤษในแอปเสร็จ นี่คือเวลาที่มันมีประโยชน์ที่สุด แต่ Cloud Run ที่ deploy อยู่ยังตอบเป็นไทย ต้อง deploy ใหม่ก่อน
  • ปัญหาใหญ่ที่สุดของการถ่าย: เวลาตอบของ Gemini บน Cloud Run วัดได้ 7–22 วินาที (มัธยฐานราว 12) ขณะที่แอปตัด timeout ที่ 20 วินาทีแล้วสลับเป็นข้อมูลตัวอย่างพร้อมป้าย "ข้อมูลตัวอย่าง" เงียบๆ คำถามพิมพ์ใช้เวลา 17–22 วินาที จึงมีโอกาสเทคพังสูง แก้ได้โดยอุ่นเครื่อง ตัดเวลารอตอนตัดต่อ และเสนอให้ขยาย timeout (แก้โค้ดบรรทัดเดียว)
  • สิ่งที่ต้องลดจาก storyboard เดิม: ฉากวางอีเมลแล้ว Gemini สกัดนัด ยังไม่มีหน้าจอในแอป และทริปที่สร้างจากการสกัดยังถูกส่งต่อให้ตัดสินใจไม่ได้ (ได้ 404) จึงแนะนำ ตัดออกจากวิดีโอ ไปพูดใน deck แทน เพื่อไม่แสดงของที่ไม่มีจริง
  • ข้อความของ Gemini ไม่ตรงกับที่ storyboard เก่าเขียนไว้: เช่นเวลา 16:10 Gemini ตอบ "ออกตอนนี้เลย (16:10 น.)" ไม่ใช่ "ออกก่อน 16:45" ดังนั้น บทพูดที่อ้างถ้อยคำของแอปต้องเขียนหลังอัดหน้าจอ ไม่ใช่ก่อน
  • เปลี่ยนโครงเรื่องหลังผู้ตรวจกรรมการวิจารณ์: เปิดด้วยคำตัดสินที่ 18:52 แล้วย้อนกลับ, ลดฉากพูดนำ, ปิดวงจรชุมชน (รูป → หลักฐาน → คำตัดสินของอีกคนเปลี่ยน) ซึ่งเป็นฉากเดียวที่พิสูจน์ Gemini หลายรูปแบบ + การเรียก tool + ผลต่อชุมชนพร้อมกัน และตัดฉากพิมพ์คำถามออก (เสี่ยงที่สุดและได้คะแนนน้อย)
  • งานนี้พึ่งพางาน "สมอง AI" อีกฉบับ: ถ้าจะพูดว่า "AI ตรวจกับเอนจินก่อนตอบทุกครั้ง" ต้องทำแถว 3 และ 5 ของตาราง P0 ใน ai-brain-pipeline.html (guard สมมาตร + ตัวตรวจตัวเลข) ให้เสร็จก่อน ไม่เช่นนั้นให้ใช้ประโยคที่จริงอยู่แล้ว (ดูหัวข้อ 10)

6.1 เครื่องมือและรูปแบบ

  • อุปกรณ์: iOS Simulator iPhone 17 Pro (ติดตั้งแล้วในเครื่อง ยังไม่ได้เปิด) ไม่มี Android emulator ซิมูเลเตอร์ไม่มีกล้อง ใช้ปุ่มเลือกรูปจากคลัง (ลากไฟล์รูปใส่ซิมูเลเตอร์ก่อน) ซิมูเลเตอร์ iOS รันได้เฉพาะโหมด debug (ไม่รองรับ --release/--profile) ป้าย DEBUG ปิดอยู่แล้วใน main.dart เฟรมแรกช้ากว่า ให้รันอุ่นเครื่องหนึ่งรอบก่อนอัด
  • กรอบภาพ: ซิมูเลเตอร์เป็นแนวตั้งราว 1206×2622 ไม่ใช่ 16:9 แนะนำผ้าใบ 1920×1080 วางโทรศัพท์ตรงกลางซ้าย (สูง 1080 → กว้างราว 497 px ตัวอักษรในแอปราว 20 px ค่อนข้างเล็ก ให้ครอป/ซูม 120–130% ตอนอ่านตัวเลข) เหลือพื้นที่ขวาไว้ใส่คำบรรยายและป้าย ยังไม่พบกฎเรื่องสัดส่วนภาพ ให้ตรวจในแดชบอร์ด
  • แถบสถานะ: xcrun simctl status_bar booted override --time 16:10 --batteryState charged --batteryLevel 100 --cellularMode active --cellularBars 4 --wifiBars 3 --operatorName "" (เปลี่ยนเวลาให้ตรงฉาก)
  • ตำแหน่ง: Features → Location → Custom Location = 13.8130, 100.5765 ก่อนฉากรูป
  • อัด: xcrun simctl io booted recordVideo --codec h264 --force take.mov หยุดด้วย Ctrl+C เท่านั้น (ไม่เช่นนั้นไฟล์ไม่สมบูรณ์) ไฟล์เป็นอัตราเฟรมแปรผัน ให้แปลงเป็น 30 fps คงที่ก่อนตัดต่อ: ffmpeg -i take.mov -r 30 -c:v libx264 -crf 14 -pix_fmt yuv420p take_cfr.mp4 ไม่มีวงกลมแสดงการแตะ ต้องเพิ่มตอนตัดต่อ (งบเวลา ~2 ชม.) อัดแต่ละฉากอย่างน้อย 2 เทค
  • เสียง: 48 kHz/24-bit โมโน ห้องเงียบ (ในตู้เสื้อผ้า/ใต้ผ้านวมก็ได้) ที่กันลม พีค -12 dBFS ปรับรวมราว -16 LUFS true peak ≤ -1 dBTP เก็บเสียงห้อง 0.5 วินาทีไว้เติมช่องว่าง
  • ดนตรี: ไม่ใส่ หรือใช้เพลงที่มีใบอนุญาตชัดเจน (ถ่ายภาพหน้าใบอนุญาตเก็บไว้) ระดับ -28 dB ใต้เสียงพูด

6.3 วิธีรับมือเวลารอของ Gemini (ปัญหาเทคนิคหลัก)

  1. อุ่นเครื่องทุกครั้งที่เว้นเกิน 10 นาที (Cloud Run ตั้ง min-instances 0 จึงหดเหลือศูนย์): ยิง curl -s -X POST $URL/v1/decide -H 'X-Demo-Clock: 16:10' -H 'Content-Type: application/json' -d '{"trip_id":"cal-dinner","mode":"car"}' 3 ครั้ง (ตรวจรูปแบบ body กับ api/README.md ก่อน) และพิจารณา deploy ด้วย --min-instances 1 ตลอดช่วงถ่ายและช่วงตัดสิน
  2. ทิ้งเทคที่เห็นป้าย "ข้อมูลตัวอย่าง" เสมอ เพราะแปลว่าคำขอ timeout และแอปสลับเป็นข้อมูลสำรอง และจดบันทึกเทค (take log) ทุกครั้ง
  3. ตัดช่วงรอตอนตัดต่อ และพูดตรงๆ หนึ่งครั้งว่า "Gemini takes about ten seconds; we cut the wait" (อย่าทำให้ดูเหมือนตอบทันที)
  4. ถ้าแก้โค้ดได้ (D5): ขยาย timeout ของ decide ในแอปจาก 20 เป็น ≥ 45 วินาที แต่ผู้ใช้จริงจะเห็นตัวหมุน 45 วินาที ตัวแก้ที่ดีกว่าคือลดความหน่วงของ agent (ดูแผนสมอง AI)
  5. ฉากโหมดน้ำท่วมถ่ายบน API ในเครื่องได้ (ไม่ใช้ Gemini) ส่วน ฉากรายงานรูปต้องถ่ายกับ API ที่มี GEMINI_API_KEY เท่านั้น เพราะหน้าผลลัพธ์พิมพ์ "Gemini has looked at it" เสมอ (report_screen.dart:355) แม้ผลจะเป็นค่าคงที่ของระบบสำรอง ห้ามถ่ายบน API ไม่มี key

6.4 ตัดต่อ

  • คำบรรยาย: ทำทั้งแบบฝังภาพ (ขาว ตัวสูง 36–40 px ที่ 1080p กล่องดำโปร่ง 60% ไม่เกิน 2 บรรทัด บรรทัดละ ≤ 42 ตัวอักษร วางนอกพื้นที่โทรศัพท์) และไฟล์ .srt อังกฤษอัปโหลดคู่กันเพื่อให้กรรมการเปิดปิดได้ ถ้าจอเป็นภาษาไทย (กรณี D1 สำรอง) ต้องมีซับอังกฤษแปลข้อความบนจอด้วย ในโหมดอังกฤษชื่อจุดเสี่ยงน้ำท่วมของ กทม. ยังเป็นภาษาไทย ต้องใส่คำบรรยายหรือเลือกเส้นทางที่ไม่เจอชื่อเหล่านั้น
  • กรอบปลอดภัย: ข้อความและป้ายอยู่ในกรอบ 5% (ซ้าย/ขวา ~96 px บน/ล่าง ~54 px) และเหนือแถบล่าง 12% ที่ YouTube ทับด้วยแถบควบคุม ไม่พึ่งสีอย่างเดียวบอกสถานะ ไม่มีแสงวาบ แต่ละตัวเลขอยู่บนจออย่างน้อย 2 วินาที
  • ป้ายบังคับบนจอ: "Scripted storm replay", "Simulated user counts", "Demo calendar account", "In-app alert (push in production)" ให้เห็นอย่างน้อย 2 วินาทีเมื่อเกี่ยวข้อง
  • ใส่วงกลมแสดงการแตะ และซูมเข้า 1.15× เมื่ออ่านตัวเลข
  • แทรกฉากสลับภาษา (Settings → Language → ไทย) 4 วินาทีในฉากปิด ถ้าเวลาเหลือ เพื่อบอกว่าสร้างมาเพื่อคนกรุงเทพฯ

10ทะเบียนคำพูด: ประโยคไหนพูดได้

ทุกประโยคที่พูดหรือเขียนบนจอต้องย้อนไปหาหลักฐานได้ เพราะกติกาห้ามข้อมูลเท็จ และกรรมการสายเทคนิคจะลองถามหรือเปิดโค้ด ฉบับแรกของแผนนี้เองมีประโยคในบทที่ขัดกับทะเบียนนี้ 4 จุด ฉบับนี้แก้แล้ว และตรวจซ้ำกับบทใหม่

คำพูดในบทใหม่สถานะหลักฐาน / เงื่อนไข
"Fon Tok Mai tells Miw: leave the car. 24 centimetres of water ahead." (ที่ 18:52)พูดได้ + ติดป้ายจำลองเป็นพายุที่เขียนไว้ (replay) รายงานผู้ใช้ในข้อมูลเป็นชุด seed ผลจริงต้องวัดซ้ำหลัง deploy
"a Gemini agent that answers that question"พูดได้Gemini ตอบจริงบน Cloud Run (generated_by: gemini ตรวจวันนี้) · มี function calling 7 tools
"It reads her calendar"พูดได้ + ติดป้ายบัญชีเดโม (mock) ไม่ใช่ OAuth จริง
"checks the rain along her route"พูดได้ข้อมูลฝนตามเส้นทางมาจากชุดพายุ (scenario) ไม่ใช่ "real" จึงตัดคำว่า real แล้ว และห้ามอ้างว่าใช้ข้อมูลสดจนกว่าจะยืนยันโหมดสดบน Cloud Run
"shows the answer before she asks"พูดได้ + ติดป้ายแบนเนอร์ในแอปหลังเปิดแอป ไม่ได้ทำงานเบื้องหลัง จึงไม่พูดว่า "on its own" แล้ว
"Here it's an in-app alert; in production, a push"พูดได้เป็น overlay ในแอป ไม่มี FCM
"The same trip is rated differently for each vehicle"พูดได้ เมื่อภาพบนจอแสดงจริงต้องเห็นชิปความเสี่ยงต่างกัน ที่ 16:10 ต่ำทุกวิธี ที่ 18:52 รถ/มอไซค์สูง รถไฟฟ้ากลาง (ผลวัดบนระบบสำรอง ต้องวัดซ้ำบน Gemini) อย่าผูกกับ 17:15 เพราะรถและมอไซค์ได้ verdict เดียวกัน
"Our risk engine uses about 15 cm for a sedan, 10 for a motorbike"พูดได้ค่าคงที่ในเอนจิน (decision.go) เป็นขีดของทีม ไม่ใช่มาตรฐานภายนอก จึงพูดว่า "our risk engine uses"
"Gemini calls its tools through function calling… and a risk engine"พูดได้ลูป agent เรียก 7 tools จริง (prompt บังคับ 4 ตัวหลัก จึงไม่พูดว่า "chooses which")
"The risk engine, not the model, sets the safety limits"พูดได้ (ขอบเขตแคบ)ขีดอยู่ในเอนจิน และกัน leave_now ตอนเสี่ยงสูง (decide.go:378) ไม่ใช่ทุกกรณี
"It runs on Cloud Run"พูดได้Cloud Run ตอบ ตรวจวันนี้ (/v1/healthz 0.14 วินาที)
Version A: "Gemini looks at it, estimates the depth and says which vehicles can pass"พูดไม่ได้จนกว่าตรวจต้องทดสอบ vision บนแบ็กเอนด์ที่ใช้ถ่ายกับไฟล์รูปจริง และเห็น generated_by: gemini ก่อน
Version B: "The app analyses it and alerts simulated commuters"พูดได้ตรงกับสิ่งที่ระบบสำรองทำจริง: จำนวนมาจากผู้ใช้จำลอง
"the report is one more tool result, and her answer changes"พูดได้เมื่อเห็นบนจอรายงานที่ส่งเปลี่ยนคำตัดสินถัดไปจริง (วัดแล้วว่า 2 → 4 รายงาน) แต่ต้องเก็บเทคที่คำตัดสินเปลี่ยนให้เห็น
"Water will reach her door in forty minutes… Rule-based, on a scripted storm"พูดได้ข้อความจริงจาก homestatus.go:170 ไม่ใช้ Gemini ตัวเลขจากชุดพายุที่เขียนไว้
"Resilience and informed decisions"พูดได้ถ้อยคำจากนิยามธีมทางการ
"Code and live API are linked below" / "Try it at …"ขึ้นกับ D7พูด "Try it" ได้เฉพาะเมื่อลิงก์เปิดแล้วเห็นแอป
"every answer is checked" / "blocks it"พูดไม่ได้ต้องทำแถว 3 และ 5 ของตาราง P0 ในแผนสมอง AI ก่อน
"19 scenarios, zero unsafe answers" / ตัวเลข scorecardพูดไม่ได้19/19 ปัจจุบันเป็นของระบบสำรอง ต้องรันกับ Gemini จริง และ "ปลอดภัย" ในที่นี้คือ "ไม่ละเมิดขีดของเอนจิน" ไม่ใช่ความปลอดภัยจริง
"Uses live Google Weather / Routes data", "WeatherNext", "Flood Hub"ยังไม่ยืนยัน/ห้ามอ้างเดโมใช้ชุดพายุ ยังไม่ยืนยันโหมดสดบน Cloud Run ส่วน WeatherNext ยังไม่ได้ต่อ
